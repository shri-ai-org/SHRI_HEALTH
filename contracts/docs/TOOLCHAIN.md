## 2. Decision: OpenAPI 3.1 (ADR-0002)

**Accepted by Vimal on 2026-10-22**, together with the 7-day rule in §5. Still needs Thulasi (CI) and Minalini (client) per ADR-0002.


- **3.1, not 3.2.** The mock server, Prism, lists support up to 3.1 only. Choosing 3.2 would break Stage 5. Spectral, oasdiff and Schemathesis already support 3.2, so we can move when Prism does.
- **3.1, not 3.0.** 3.1 is aligned with JSON Schema 2020-12 (cleaner nullability, `examples`, `const`), and every tool in §1 supports it.
- **Version string.** PROPOSED: `openapi: 3.1.2`, the latest 3.1 patch (patch releases are clarifications only). **Verify in Stage 5** that Prism, Spectral, Redocly, oasdiff and Schemathesis accept `3.1.2`; fall back to `3.1.0` if any rejects it.

## 3. File layout (VD-G8)

One file per module plus shared components, bundled into one file for tools.

```
contracts/
├── docs/                         # these documents
└── openapi/
    ├── shri-health.yaml          # root: info, servers, security, tags, and $refs to module paths
    ├── shared/
    │   ├── common.yaml           # Id, Instant, PartialDate, Money, Quantity, Coding, Address, HumanName, Phone…
    │   ├── problems.yaml         # Problem, ValidationProblem, error-code enum, standard error responses
    │   ├── pagination.yaml       # limit, cursor, list envelope
    │   ├── headers.yaml          # Idempotency-Key, If-Match, ETag, X-Request-ID, RateLimit, Retry-After…
    │   ├── operations.yaml       # Operation schema
    │   ├── security.yaml         # security schemes
    │   └── events.yaml           # event envelope and event payloads
    ├── modules/
    │   ├── platform.yaml  files.yaml  practice-setup.yaml
    │   ├── patients.yaml  scheduling.yaml  eligibility.yaml  encounters.yaml  history.yaml  ai.yaml
    │   ├── medications.yaml  orders.yaml
    │   ├── billing.yaml  documents.yaml  ccda.yaml  inbox.yaml  exports.yaml
    │   └── communications.yaml  dashboards.yaml
    ├── examples/                 # synthetic examples, one folder per module
    ├── rules/                    # Spectral custom functions (JavaScript)
    ├── .spectral.yaml            # lint ruleset (CONTRACT_GOVERNANCE §5)
    ├── redocly.yaml              # bundler configuration
    └── dist/
        └── shri-health.bundled.yaml   # generated by `redocly bundle`; committed; CI fails if stale
```

| Rule | Reason |
|---|---|
| Each module file holds that module's paths and module-specific schemas | Owners review one file (VD-SIGN) |
| Shared schemas only in `shared/`; modules never copy them | One definition of each thing (your rule 4) |
| Module files may reference `shared/` and, rarely, another module's schema; never circular | Keeps bundling predictable |
| `dist/` is generated, never edited by hand; committed so Prism, oasdiff, Schemathesis and the TS generator all read one file | Tools work on a single document (VD-G8) |
| **PROPOSED:** CODEOWNERS adds the implementing owner to each module file (e.g. `/contracts/openapi/modules/billing.yaml @vimal @anand`) | Makes "owners approve their sections" enforced by GitHub, not just by habit. Needs Thulasi (owns `.github/`) |

## 4. Commands (Stage 5 will script these)

```bash
npx @redocly/cli@<pinned> bundle contracts/openapi/shri-health.yaml -o contracts/openapi/dist/shri-health.bundled.yaml
```

```bash
npx @stoplight/spectral-cli@<pinned> lint contracts/openapi/dist/shri-health.bundled.yaml --ruleset contracts/openapi/.spectral.yaml
```

```bash
npx @stoplight/prism-cli@<pinned> mock contracts/openapi/dist/shri-health.bundled.yaml
```

```bash
oasdiff breaking <main bundled file> contracts/openapi/dist/shri-health.bundled.yaml --fail-on ERR
```

These go into an npm `package.json` inside `contracts/` with exact versions and a lockfile, so `npx` never fetches an unpinned version. **PROPOSED.**

## 5. Version policy

| Rule | Reason |
|---|---|
| Exact versions in `contracts/package.json` and `package-lock.json`; no `^` or `~` | Reproducible CI |
| Adopt a release only once it is at least 7 days old | Several tools released yesterday (Redocly, oasdiff, orval, Schemathesis); a short wait avoids broken or compromised releases |
| Re-check versions at Stage 5 and then monthly; record the check date here | Your rule 5 |
| OWASP ruleset 2.0.1 has had no release since March 2024. **PROPOSED:** use it, but copy the rules we rely on into `rules/` if it stops working with the Spectral version we pin | It is still the standard Spectral security ruleset; we must not depend on an unmaintained package silently |
| Node 24 LTS in CI (Thulasi) and locally | LTS = maintained |

## 6. CI jobs (proposal to Thulasi; she owns `.github/`)

| Job | Runs | Fails when |
|---|---|---|
| `contract-bundle` | Redocly bundle, then `git diff --exit-code contracts/openapi/dist/` | The committed bundle is stale |
| `contract-lint` | Spectral with our ruleset | Any `error` rule fails (CONTRACT_GOVERNANCE §5) |
| `contract-breaking` | oasdiff against `main`'s bundle | A breaking change without the `breaking-change-approved` label (CONTRACT_GOVERNANCE §4) |
| `contract-mock-smoke` | Start Prism, call a few endpoints | Mock does not start or returns invalid examples |
| `client-generated` | Regenerate the TS client, `git diff --exit-code frontend/src/api/generated/` (TW §4) | Screens use a stale client (Minalini's generator) |
| `contract-tests` (later) | Schemathesis against the running API (CONTRACT_GOVERNANCE §6) | Implementation differs from contract |
